# Admin Management Pages

## Admin Management Pages
- Returns: list with validity, remaining amount, linked tickets, duplicate voucher print.
- Locations: searchable paginated list for admins.
- General Setup: editable when `readOnly` is false, with modal form and validation.
- Item Families/Subfamilies: each on dedicated page with CRUD modals and pagination.
- **Sales Invoices** (`InvoiceManagement.vue`): admin module under the Sales menu group that manages **sales invoices** (formerly just "Invoices"). Provides date range, invoice number, and customer filters, server-side pagination, a detailed invoice modal, and uses `admin.invoiceModule.*` i18n keys (e.g. `title`, `subtitle`, `tabList`, `filters`, `refresh`).
- **Inventory counts** (`InventoryCounts.vue`, `InventoryCountDetail.vue`, routes `admin-inventory-counts` `/admin/inventory-counts` and `admin-inventory-count` `/admin/inventory-counts/:id`): menu Stock (`admin.inventory`), after Print product labels, and the search bar. Only on a store that keeps its own stock: `STOCK_ROUTES` of `navigation/store-mode-routes.js`, hidden with `appConfig/supplyFromErp` by the router guard, the menu and `hiddenStoreRoutes`; no head office route. Resource `admin-inventory-counts`: `read` shows the pages, `write` shows New count, Import the file again, Delete and Validate (Roles page, group Stock). List: number, count date, note, status, rows read, created by, validated at and by, newest first, paged. New count (`components/admin/inventory/InventoryImportModal.vue`): count date (today), note, file (.xlsx / .xls), a model file made in the browser (Code, Quantity; codes as text); the count opens after the import. One count: summary cards, a yellow banner when cashier sessions are open and one when lines will not be applied, filter all / differences / problems, search, the lines paged by the backend (difference green up, red down). A draft can be imported again, deleted, validated (a confirmation with the items that change, the totals up and down, cannot be undone); a validated count is read only with who and when. Import and validation: overlay or spinner, buttons disabled, timeout 600 s; the requests pass `skipErrorPopup` and the backend's `{"error"}` shows once in a toast. API and rules: `modules/inventory-count.md`.
- **RFID** (3.1.0, `views/admin/rfid/RfidReaders.vue`, `RfidPosMachines.vue`, routes `admin-rfid-readers` `/admin/rfid/readers` and `admin-rfid-pos-machines` `/admin/rfid/pos-machines`): store menu RFID, only when `/config` `rfidEnabled` (`RFID_ROUTES` of `navigation/store-mode-routes.js`: menu, router guard, search bar); permissions `read:admin-rfid-readers`, `read:admin-rfid-pos-machines`. Readers: CRUD, Test connection, Test read (popup with the tags, Read again). POS machines: CRUD, the reader among the active ones, "This PC" from `GET /rfid/my-machine` and "Add this machine". Every request `skipErrorPopup`, the backend's `{"error"}` shown as it comes. Details: `modules/rfid.md`.
- **Articles** (store, `views/admin/ItemManagement.vue`, route `admin-item-management` `/admin/item-management`, resource `admin-item-management`). **3.1.2: on every store** (standalone, supplied by its head office, NAV items, catalogue from the ERP) the list is the head office's `views/admin/headoffice/ItemCards.vue` in `context="store"` (`GET /item-catalogue`, core `ItemCatalogueService`); the flat list of before (`GET /item-barcode/items-with-barcodes`, still read by the labels page and the till) is gone from this page. One line per NAV item number, else one per item: code (natural sort), name, classification, variants count where items carry NAV numbers, **price with VAT** to the millime (a range for a NAV item; a single item's price before VAT and its VAT in the tooltip; in clearance below its public price, that price struck and the "Soldé" badge; the store's own price on a head office item, the "Prix magasin" badge with the head office's price with VAT in its tooltip), the ERP's maximum discount (a catalogue from the ERP only), **stock** where the store keeps its own (sortable on the server, `sort=stock`; red below 0; "Stock bas" at or under a single item's minimum), the **weighted average cost** (CMP, before VAT, a range for a NAV item) only when the API sends it (`withCost`: own stock and a role with `write:admin-item-cost` or `read:admin-margins`, checked by `StoreItemCatalogueAPI`), status (3.1.2: no action column, the actions are in the item card). A head office item (store whose catalogue comes from its head office) is marked by a quiet house icon after its name ("Siège" in its tooltip). The page's notice (no Add button: purchase right off) shows above the table with the filter chips. What the old list showed beyond the grouped columns comes with each line (`ItemCatalogueService.storeDetails`, one read for the page: origin, own price, head office price, price before VAT and VAT, clearance public price, minimum stock, maximum discount, cost; left out of the JSON when null, so the head office's answer is unchanged). Filters: search (name, NAV code, an item or variant code, barcode; debounced), status (All by default, Active, Inactive), price with VAT (the old list filtered before VAT), the classification levels (catégorie and section only where they exist, each narrowing the ones below), kept in the URL with the sort and the page; 3.1.2, "Coût: Sans coût" where the list shows the CMP (`withCost`): the items without a CMP, services, discount items and packs left out (`withoutCost=true`, `StoreItemCatalogueAPI.WITHOUT_COST`, ignored by the API without `withCost`; URL `withoutCost=1`); no card, pack, stock adjustment, point de stock, division or "has variants" filter here. "Ajuster le CMP" on an item without a CMP pre-fills the reason "Coût initial" (editable; its history row: old cost null). A NAV item's line opens and closes its variants in the list (`GET /nav-item/variants`, the status filter's; their own clearance, stock, cost and maximum discount); a search that found some of its variants but not all (a variant code, a barcode: `matchedItemIds` of the line) opens the line by itself with those variants highlighted. A variant or a single item opens the **item card** (3.1.2, `components/admin/items/StoreItemCard.vue`, the head office card's look; no row menu and no action column any more): header (code, name, badges active / type / Siège or ERP / Soldé / Prix propre, previous and next of the list or of the NAV item's variants, ← →), band (image, classification, VAT, unit, shown at the till, stock; price with VAT, struck in clearance, before VAT; the item's **actions**), tabs **Général** (code, name, description, type, family, sub-family, the variant's fields for a NAV item, unit, brand, category, discount group, shown at the till), **Prix et coûts** (before VAT, VAT, with VAT, public price in clearance, head office price with an own price, maximum discount; the CMP, the last direct costs and the margin before VAT on the CMP only where the store keeps its own stock and with `write:admin-item-cost` or `read:admin-margins`), **Stock** (where the store keeps its own: quantity, minimum, the last 20 movements, 100 on demand, `GET /item/{id}/stock-movements`: without a cost right the API leaves out the CMP adjustments and every price), **Codes-barres**, **Composition** (a pack) and **Variantes** (a NAV item: its variants, a click shows one). The actions (`libs/item-card.js` `cardActions`, checked by `tools/store-item-card-check.mjs`) are the old row menu's rules (`itemRowActions`, `libs/item-management.js`) without View and Barcodes, plus "Ajuster le CMP" (own stock, `write:admin-item-cost`, not a pack): a local item Modifier (closes the card, opens the item form), Ajuster le stock, Ajuster le CMP, Supprimer; a head office item Modifier le prix / Revenir au prix du siège with the store's price right, Ajuster le stock, Ajuster le CMP; an item of a catalogue from the ERP Configurer le pack. The page runs them with its windows (above the card) and reads the card and the list again; a deletion closes the card. The item form is now only the creation and the edit of a local item (consult-only stays for a head office item, a NAV item and a catalogue from the ERP if reached). The variant link "Toutes les variantes de cet item NAV" closes the card and lists that NAV item, opened. The Add button stays where the page offers it. The head office's "Gestion des articles" page (route `admin-headoffice-items`, the same component, a head office that owns its catalogue) shows the same list on the head office's read (`GET /admin/headoffice/item-catalogue`, `listApi`), without the store's details. The old "Articles ERP" page (`NavItems.vue`) is gone: its route `admin-nav-items` (`/admin/nav-items?q=`) sends on to Articles with its search (`libs/item-catalogue-view.js` `navItemsRedirect`). **Excel export** (3.1.2, "Exporter Excel" in the header; the store's own list only, not the head office's `listApi`): `GET /item-catalogue/export` with the list's filters and sort, no page (`StoreItemCatalogueAPI.criteria`, the same criteria as the list): every item of the lines the list shows, one row each (a NAV item's variants of the status, as the line opens on), in the list's sort read on the item (stock, price), then by code; at most 60,000 rows (`ItemCatalogueService.EXPORT_MAX`; beyond, `truncated` and a warning toast). One query (`ItemCatalogueQuery.items`: the list's joins and WHERE on the item rows, the line conditions on window values; 0.22 s for the 21,907 variants of the ZEN test store). A row: NAV item number, code, variant, name, barcode (the primary of `item_barcode`, else the item's own, else its first), catégorie, family, sub-family, section, price before VAT, VAT %, price with VAT, the clearance public price with VAT (the till's rule), stock and minimum (own stock only), CMP (`withCost` only, as the list), maximum discount, unit, origin and own price (a store supplied by its head office), status; a column only when a row fills it (`libs/items-export.js`). Real numbers with their Excel format, an autofilter, widths from the content (`libs/excel-export.js`); file `articles-<day>.xlsx`. Checked by `ItemCatalogueExportQueryTest` and `tools/excel-exports-check.mjs`. ## Admin UI Enhancements

### Tickets History Page (`TicketsHistory.vue`)
**Features:**
- **Synchronization Status Display:**
  - Sync status column in tickets table with color-coded badges (green: Totally Synced, yellow: Partially Synced, gray: Not Synced)
  - ERP document number displayed below sync status badge
  - Sync status filter dropdown (All, Not Synced, Partially Synced, Totally Synced)
  - Synchronization info section in ticket details modal showing:
    - Sync status with icon
    - ERP document number
    - Lines synchronized count (e.g., "3 / 5")
  
- **Enhanced Sales Lines Display:**
  - Shows discount percentage and amount
  - Shows VAT percentage and amount
  - Shows unit price TTC (including VAT)
  - Shows line total TTC (including VAT)
  - Synced indicator for each line (green "Synced" or gray "Not Synced" badge)
  
- **Currency:**
  - All prices displayed in TND (Tunisian Dinar) instead of USD ($)
  - Format: "XXX.XX TND"
  
- **Filter Panel:**
  - Collapsible filter section (closed by default)
  - Two-row layout for better organization:
    - Row 1: Search (larger), Date From, Date To
    - Row 2: Status, Sync Status, Payment Method (all equal width)
  - Icons for each filter field (Search, Calendar, Tag, Cloud, Credit Card)
  - Ticket count moved to filter header: "Filters (Total: X tickets)"
  - Compact padding and spacing
  
- **UI Improvements:**
  - Removed Cashier column from tickets table (still shown in details modal)
  - Cleaner, more focused table layout
  - Enhanced details modal with better organization
  - Responsive design for all screen sizes

- **Excel export** (3.1.2, "Exporter Excel" in the header): `GET /sales-header/history/export` with the list's filters,
  no page (`SalesHeaderService.ticketsHistorySpec`, the list's own filters since then; `TicketsHistoryExport`). Every
  ticket of the filters, newest first, at most 20,000 (`MAX_TICKETS`; beyond, the newest ones, `truncated` with
  `totalTickets`, a warning toast asking for a shorter period). A few reads whatever the number: the tickets in one
  query (customer, user, session and its cashier, loyalty card joined), the lines and the payments by blocks of 1,000
  ids. Two sheets:
  - **Tickets**: n°, date (a real Excel date), status, cashier (the ticket's user, else the session's), session,
    customer code and name, loyalty card, lines, quantity, HT and VAT before the ticket's discount (as recorded),
    discount with VAT, total with VAT, **one column per payment method** (the methods of the tickets in their display
    order), paid, change, loyalty points, ERP status and number (sales to an ERP), invoiced, invoice n°, tax ID, notes;
  - **Lignes**: n° and date of the ticket, item code, item (with its variant, the till's label), family, sub-family,
    quantity, unit price before and with VAT, discount % and with VAT, VAT % and amount, totals before and with VAT, and
    the unit cost frozen at the sale only with `read:admin-margins` (`withCost`).

  An optional column only when a row fills it (`libs/tickets-export.js`); file `tickets-<from>_<to>.xlsx` of the
  period. Checked by `TicketsHistoryExportTest` and `tools/excel-exports-check.mjs`.

### ERP Communications Page (`ErpCommunications.vue`)
**Features:**
- **Enhanced Details Modal:**
  - URL section at top with copy button
  - Operation details section with icons
  - Error messages with icons
  - Request/Response payloads with copy buttons
  - Improved visual hierarchy and styling
  
- **Table:**
  - URL column removed from list (only shown in details modal)
  - Cleaner table layout
  - Search includes URL field
  
- **Field Changes:**
  - `externalReference` field replaced with `url` field
  - URL stores the actual HTTP endpoint URL used for the operation
  - Better tracking of which ERP endpoint was called

**Backend Changes:**
- `ErpCommunication` entity: `externalReference` → `url` (String, length 512)
- `ErpCommunicationViewDTO`: Updated to use `url` field
- `ErpCommunicationService.logOperation()`: Accepts `url` parameter instead of `externalReference`
- All ERP connectors capture and return URL in `ErpOperationResult`
